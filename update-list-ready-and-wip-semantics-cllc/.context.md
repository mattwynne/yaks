# Goal

Update user-facing status/readiness semantics after separating workflow state from availability.

# Why This Exists

The first slice, `model parent readiness from child completion`, may add/clarify a domain readiness rule without fully exposing it in the UI. We need to circle back here so users and agents can actually see which yaks are ready/actionable.

# Design Direction

Keep the concepts separate:

- `state`: stored workflow state (`todo | wip | blocked | done` for now)
- `ready`: derived boolean meaning "actionable now"
- later, possibly `availability`: a richer derived value such as `ready | unavailable | blocked | active | done`

For now, avoid redesigning all pretty rendering. Expose readiness in ways that are useful to agents and scripts first.

# Recommended First Slice

- Add derived `ready: true/false` to `yx list --format json`.
- Consider also adding `ready` to `yx show --format json` if there is a clean path.
- Add a user-facing way to list actionable yaks, probably `yx list --ready`.
- Keep `yx list --only not-done` semantics as "not done", not "actionable".
- Do not redesign pretty glyphs/colours yet unless needed for a minimal indication.

# Areas To Review

- `yx list` rendering
- any ready/actionable yak logic
- `yx start`, `yx done`, and `yx state`
- help text for states/status
- JSON output fields: distinguish workflow state from derived availability
- possible filters or commands for ready yaks, e.g. `yx list --ready` or future `yx prime`

# Desired Outcome

Users can tell the difference between what workflow state a yak is in and whether it is currently actionable.

# Proposed Semantics

- `--only done`: yaks whose stored workflow state is `done`.
- `--only not-done`: yaks whose stored workflow state is not `done`; this may include unavailable parents.
- `--ready` or equivalent: yaks whose derived readiness is true.
- JSON should expose both stored `state` and derived `ready` so consumers do not have to infer readiness from tree structure.

# Open Questions

- Should ready be exposed as `yx list --ready`, `yx list --only ready`, or both?
- Should `ready` appear in `yx show --format json`, or only list JSON initially?
- Should pretty list annotate unavailable todo parents, or is a ready filter enough for now?
- How should a wip yak with blockers render once explicit blockers exist?
