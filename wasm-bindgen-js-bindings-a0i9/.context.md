Expose Yaks domain operations to JS via wasm-bindgen.

# Status Update

This yak previously listed `stuck` as a workflow state and depended on "add stuck state". That is stale.

Yaks workflow state is now only:

- `todo`
- `wip`
- `done`

Blocked/readiness should be exposed separately via blockers and derived readiness.

# Minimum API Surface for Disco Integration

- Load events from serialized form → build YakMap
- Add yak (name, parent_id)
- Set workflow state (`todo`, `wip`, `done`)
- Add/remove blockers, including manual blockers if Disco `blocked` maps that way
- Remove yak
- Rename yak
- Get projected tree/list including hierarchy, state, readiness, and blockers
- Serialize events for persistence

The WASM module does NOT do git I/O — that stays in JS/isomorphic-git. The boundary is: JS handles persistence, WASM handles domain logic.

# Prerequisite

Revisit Disco status mapping under the new workflow-state/readiness model before deciding the final binding shape.

Do not add `stuck` as a workflow state without a fresh design decision.
