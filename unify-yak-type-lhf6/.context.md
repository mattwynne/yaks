# Unified Yak Struct

pub struct Yak {
    pub id: YakId,
    pub name: Name,
    pub parent_id: Option<YakId>,
    pub state: YakState,
    pub context: Option<String>,
    pub fields: HashMap<String, String>,
    pub tags: Vec<String>,
    pub created_by: Author,
    pub created_at: Timestamp,
}

- children is excluded - it is derived/computed by scanning other yaks for matching parent_id. YakMap already does this via find_children_of(). Compute at the read/presentation layer when needed.
- id is redundantly stored inside the value (as well as the HashMap key) for convenience.
- YakSnapshot can either disappear entirely or become a trivial type alias / From<&Yak>.

# Event Store Impact Analysis

**Existing persisted events are NOT affected.** Events are text-based strings like `"Added: \"test\" \"test-a1b2\""` and `"FieldUpdated: \"test\" \".state\""`. The Rust types are in-memory representations only.

**Compacted events:** The `YakEvent::Compacted` variant holds `Vec<YakSnapshot>`. Key findings:
- `compact()` in git.rs calls `tree::read_snapshots_from_tree()` to build snapshots from the git tree, then wraps them in `YakEvent::Compacted(snapshots, metadata)`
- `get_all_events()` reads Compacted commits by calling `tree::read_snapshots_from_tree()` on the compaction commit's tree
- `read_snapshots_from_tree()` in tree.rs builds `YakSnapshot` from git tree blobs (reads .name, .state, .context.md, .parent_id, .created.json, custom fields)
- The git tree does NOT store `tags` — so `YakSnapshot` currently has no `tags` field
- When building a Compacted tree (`build_tree_from_event` Compacted branch), it writes snapshots using `YakSubtreeBuilder` which also has no tags support

**Decision for tags in Compacted/snapshots:** Since the git tree doesn't store tags, and `YakSnapshot` doesn't have tags, the simplest approach is:
1. If replacing `YakSnapshot` with `Yak`, default `tags` to `vec![]` when reading from git tree in `read_snapshots_from_tree()`
2. OR keep `YakSnapshot` as a slim type without `tags` and implement `From<&Yak>` (dropping tags)

Option 1 is cleaner — just use `Yak` everywhere with `tags: vec![]` for snapshots.

**`merge_event_streams()` in event_store/mod.rs** accesses `snapshot.id` when checking orphan events against compacted snapshots. This just needs `Yak` to have an `id` field (which it does).

# Approach
1. Create the unified `Yak` struct in `src/domain/yak.rs` (replacing `YakView`)
2. Remove `YakEntry` from `yak_map.rs` — replace with `Yak`
3. Remove or simplify `YakSnapshot` — either replace with `Yak` directly, or make it `From<&Yak>`
4. Update `YakMap` aggregate to hold `HashMap<YakId, Yak>`
5. Update `ReadYakStore` trait to return `Yak` instead of `YakView`
6. Update all adapters (DirectoryStorage, InMemoryStorage) to construct `Yak`
7. Update `tree::read_snapshots_from_tree()` to return `Vec<Yak>` with `tags: vec![]`
8. Update `YakEvent::Compacted` to hold `Vec<Yak>`
9. Update `merge_event_streams()` references
10. Update all re-exports in `src/domain/mod.rs`
11. Update all call sites across the codebase

## Key concern: `children` field removal
`YakView` has `children: Vec<YakId>` which the stores currently populate. With `Yak`, this is removed. The presentation/view layer code that builds `YakDetailView` and `YakTreeNode` will need to compute children by scanning `parent_id` fields. Check how `children` is used in the application layer and ensure it's computed at the right level.
