## Problem

The JSON output from `yx show --format json` is missing important information
and leaks presentation concerns into the view model.

### Missing IDs

No yak IDs appear anywhere in the output — not on the yak being shown, not on
its children, and not on ancestors. The `YakDetailView` and `YakChildView`
structs simply don't carry IDs. This makes the JSON output much less useful for
tooling (e.g. the `show_yak` pi extension) because there's no way to
programmatically refer back to a yak after reading its details.

### Presentation-leaky breadcrumbs

`YakDetailView` has `breadcrumb: Vec<String>` — a flat list of ancestor names,
pre-formatted for display. This is a presentation concern that's leaked into
the view model. The view model should provide structured data; the display
adapter should decide how to format it.

Ancestors should use the same structure as children — carrying id, name, and
state — so any consumer can work with them uniformly.

## Underlying modelling issue

There's no lightweight domain type for "a reference to a yak." We have:
- `YakView` — a full read-model DTO with context, fields, tags, children
- `YakSnapshot` — a serialization shape for compacted events
- `YakChildView` — a presentation-only struct with just name and state

What's missing is a simple value object like `{id, name, state}` that can be
used anywhere you need to refer to a yak: ancestors, children, search results,
the shown yak itself. Whether this lives in the domain or the view layer is a
design decision to make during implementation.

## Goal

The `show_yak` pi extension should be able to work with yak IDs — both
receiving them in the output and using them to look up yaks. Right now it can
only work with names, which are mutable and ambiguous. IDs are stable
identifiers that tooling can rely on.

## Scope

1. Add `id` to the shown yak in `YakDetailView`
2. Add `id` to `YakChildView` (or replace it with a shared type)
3. Replace `breadcrumb: Vec<String>` with structured ancestors carrying id,
   name, and state
4. Update `show_yak.rs` use case to populate the new fields
5. Update display adapters (pretty + JSON) to format from structured data
6. Update Rust tests and the show-yak pi extension test
