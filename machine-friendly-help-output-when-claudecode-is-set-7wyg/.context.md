When CLAUDECODE=1 (or more broadly, when running non-interactively), yx help output should be tailored for robots.

For example:
- Recommend `yx ls --format json` instead of `yx ls`
- Recommend `yx show --format json <name>` for structured data
- Emphasise flags that produce machine-parseable output
- Skip examples that assume human interaction

This could be:
- A different help mode triggered by CLAUDECODE=1
- A separate `yx help --for-robots` flag
- Just adjusting the examples section when non-interactive

The goal: when a robot runs `yx` or `yx --help`, it gets guidance that leads to correct, structured usage from the start.
