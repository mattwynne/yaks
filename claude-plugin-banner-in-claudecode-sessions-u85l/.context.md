# Spec: Claude plugin banner in CLAUDECODE sessions

## Goal
When running inside Claude Code (CLAUDECODE=1), nudge the user to install the yx plugin if it's not already installed.

## Scope
- In scope: banner on `yx` (bare) and `yx --help`, detection via `claude plugin list`, suppression via `yx config set show-claude-plugin-hint false`
- Out of scope: banner on every command, per-session suppression, project-level config

## Key Decisions
- Gate: CLAUDECODE=1 environment variable
- Detection: shell out to `claude plugin list` and check for yx plugin
- Frequency: only on bare `yx` and `yx --help`, not every command
- Suppression: `yx config set show-claude-plugin-hint false` (depends on yx config command)
- Banner is a one-liner with both commands chained

## Banner Text
```
Tip: install the yx plugin for Claude Code: claude plugin marketplace add mattwynne/yaks && claude plugin install yx@yaks (suppress with: yx config set show-claude-plugin-hint false)
```

## Why
A user inside Claude Code who hasn't installed the plugin is missing the skills that make yaks + Claude work well together. This is the most natural touchpoint — they're already using yx, inside Claude.

## Acceptance Criteria
- [ ] Banner shows on bare `yx` and `yx --help` when CLAUDECODE=1 and plugin not installed
- [ ] Banner does NOT show when plugin is installed
- [ ] Banner does NOT show when show-claude-plugin-hint is false
- [ ] Banner does NOT show outside Claude sessions (CLAUDECODE not set)
- [ ] Banner goes to stderr (doesn't interfere with output)
- [ ] Cucumber acceptance tests covering all four cases
