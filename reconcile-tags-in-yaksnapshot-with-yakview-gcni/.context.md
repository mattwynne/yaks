# Reconcile tags in YakSnapshot with YakView

## Status: Obsolete in original framing

**ADR 0018 unified all yak types.** `YakSnapshot` is now a type alias
for `Yak`. `YakView` no longer exists. There's one type with
`tags: Vec<String>`.

## Residual bug

The underlying issue still exists but differently:

- `read_snapshots_from_tree()` sets `tags: vec![]` — tags are lost
  when reading from the git tree
- `YakSubtreeBuilder` (used by compaction) writes `yak.fields` to the
  tree but not `yak.tags` — tags are lost during compaction
- Tags are stored via `FieldUpdated` events (field name `.tags`) and
  replayed correctly by `YakMap::apply()`, so the event-sourced
  aggregate has correct tags
- But `yx reset` (which rebuilds from the git tree) loses tags

This should probably be reframed as "fix tags lost during compaction
and tree reads" rather than a type reconciliation task.
