# Reconcile tags in YakSnapshot with YakView

## Problem

Tags are inconsistent between YakSnapshot and YakView:
- YakView has a dedicated `tags: Vec<String>` field
- YakSnapshot has no `tags` field — they end up in the `fields` HashMap
  as `.tags` (a newline-separated string) via `read_custom_fields`
- The `From<&YakView> for YakSnapshot` impl copies `fields` but drops
  `tags`, so round-tripping loses them
- `.tags` is a reserved field in the domain but treated as a custom
  field by the snapshot/tree reader

## Fix

- Add `tags: Vec<String>` to YakSnapshot (like YakView has)
- Update `From<&YakView>` to copy tags across
- Update `read_snapshots_from_tree` to parse `.tags` into the dedicated
  field (like it does for `.state`, `.context.md`, `.name`)
- Update `YakSubtreeBuilder` / compaction to write tags from the
  dedicated field
- Ensure `.tags` is excluded from `read_custom_fields` (it should
  already be in RESERVED_FIELDS — verify)
