## Problem

Tags are lost when reading yak state from the git tree. This affects:

1. **Compaction:** `YakSubtreeBuilder` writes `yak.fields` (custom fields) to
   the tree but not `yak.tags`. Tags stored via `FieldUpdated` events with
   field name `.tags` are simply dropped.

2. **`yx reset`:** `read_snapshots_from_tree()` sets `tags: vec![]` because
   the git tree doesn't have a `.tags` blob (since compaction didn't write it).

The event-sourced aggregate has correct tags (replayed via `YakMap::apply()`),
and the `.yaks/` projection has correct tags (written by the projection
listener). But any path that reconstructs state from the git tree loses them.

## Fix

1. **Write tags during compaction:** In `build_tree_from_event` for the
   `Compacted` variant, write `yak.tags` as a `.tags` blob (newline-separated)
   via `YakSubtreeBuilder`.

2. **Read tags from tree:** In `read_snapshots_from_tree()`, read the `.tags`
   blob and parse it into `Vec<String>` instead of hardcoding `tags: vec![]`.

3. **Verify `.tags` is in `RESERVED_FIELDS`** so it's excluded from
   `read_custom_fields()` (it should already be — just confirm).
