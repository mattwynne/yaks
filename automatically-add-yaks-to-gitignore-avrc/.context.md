> one very minor friction I first encountered was the implied .yaks -> .gitignore setup step. when I first received an error, I ran yx --help and instinctively scanned the command list for a yx init . could be nice to add

## Approach

When `yx` detects that `.yaks` is not in `.gitignore`, instead of crashing with an error:

1. Tell the user that `.yaks` needs to be in `.gitignore`
2. Offer to add it for them
3. If they accept, append `.yaks` to `.gitignore` and remind them they'll need to commit the change

No `yx init` command — we don't need it for any other reason.
