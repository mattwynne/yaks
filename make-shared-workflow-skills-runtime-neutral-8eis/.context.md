# Goal
Let contributors use the shared workflow skills with ordinary coding-agent capabilities, without installing Pi extensions or Superpowers.

# Files
- Modify: `skills/yak-worktree-workflow/SKILL.md`
- Modify: `skills/parallel-yak-implementation/SKILL.md`
- Modify: `skills/yak-mapping/SKILL.md`
- Modify: `skills/preparing-a-yak/SKILL.md`
- Add focused portability checks under `tests/shellspec/`

# Design
Describe required outcomes and capability checks rather than mandatory vendor-specific tool names. The baseline should use documented `yx`, git/worktree, `dev`, and whatever delegation facility the active agent provides. Pi or Superpowers integrations may appear only as optional examples and must not be required for completing the workflow.

# Specific Contradictions to Resolve
- Remove required `start_yak`, `show_yak`, `merge_yak`, Pi `subagent`, and `worker` agent schemas.
- Remove required `superpowers-dev:*` and `/brainstorming`-style dependencies, replacing them with self-contained steps or optional enhancement notes.
- Reconcile `parallel-yak-implementation` reading a `plan` field with `preparing-a-yak` correctly storing the plan as sub-yaks.
- Ensure delegation instructions do not assume unsupported `cwd` or parallel `tasks` parameters.

# Test Approach
Write one failing portability assertion at a time for mandatory undeclared capability references, then rewrite the smallest relevant workflow section. Preserve the skill's intent and safety invariants.

# Definition of Done
- A Claude Code contributor can follow every shared workflow skill using built-in shell, file, and agent capabilities.
- Other capable agents receive outcome-oriented instructions instead of Claude- or Pi-specific schemas.
- Optional runtime integrations are clearly labeled and never gate progress.
- Yak plans are read from hierarchy/context, not a contradictory required plan field.
- Focused portability tests pass.
