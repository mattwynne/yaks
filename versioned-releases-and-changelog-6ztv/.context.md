# Goal
Start versioning yaks releases and keeping a changelog, with the release process automated enough that Matt does not have to think.

# Desired outcome
- Stable releases are versioned with SemVer-style tags, e.g. `v0.2.0`.
- GitHub Releases are created automatically from tags.
- `main` continues to publish an unstable `edge` prerelease for dogfooding.
- `install.sh` defaults to latest stable release, but can install a specific version or edge.
- `CHANGELOG.md` is kept in a consistent format.
- Release workflow validates version/changelog/tag consistency before publishing.
- Release notes are generated automatically from the changelog.
- Cutting a release should be close to: run one command, review, push.

# Release UX target
Prefer a script or cargo xtask-style command, e.g.:

```bash
dev release 0.2.0
```

or:

```bash
bin/release 0.2.0
```

That command should do the boring parts:
- check working tree is clean
- check branch is main and up to date
- run `dev check`
- update `Cargo.toml` version
- update `Cargo.lock`
- move `CHANGELOG.md` `[Unreleased]` entries to `[0.2.0] - YYYY-MM-DD`
- ensure a fresh empty `[Unreleased]` section remains
- commit `Release v0.2.0`
- create annotated tag `v0.2.0`
- print the exact push command, or optionally push with confirmation

# Policy decisions
- Use SemVer, currently in `0.x`.
- Stable release tags: `vX.Y.Z`.
- Edge channel tag: `edge`.
- Edge releases are prereleases built from `main`.
- Stable releases are non-prerelease GitHub Releases built from version tags.

# First milestone
Ship this as first versioned release, probably `v0.2.0`.
