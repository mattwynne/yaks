## Problem
`yx log` panics with BrokenPipe when piped through a pager and user quits early (e.g. `q` in less).

The crash is at src/adapters/user_display/mod.rs:505 — `.unwrap()` on a `writeln!` that fails because the pipe is closed.

## Design
Extract a `BrokenPipeGuard<W: Write>` adapter that wraps any `Write` and silently absorbs `BrokenPipe` errors (returns `Ok(buf.len())` instead).

### Unit test
Wrap a mock writer that returns `ErrorKind::BrokenPipe` in `BrokenPipeGuard`. Assert writes succeed — no panic, no error.

### Wiring
In `main.rs`, wrap `stdout` in `BrokenPipeGuard` before passing it to the display adapter. All downstream `.unwrap()` calls are now safe.

### Files
- New: `src/adapters/broken_pipe_guard.rs` — the wrapper + unit tests
- Modified: `src/adapters/mod.rs` — add module
- Modified: `src/main.rs` — wrap stdout in BrokenPipeGuard before injecting into display adapters

### Acceptance
- Unit test: writing to a BrokenPipeGuard<MockWriter> where mock returns BrokenPipe → returns Ok, no panic
- All existing tests pass unchanged
- `cargo clippy` clean
