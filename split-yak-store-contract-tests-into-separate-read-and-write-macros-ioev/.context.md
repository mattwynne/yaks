# Split yak store contract tests into separate read and write macros

## What

The `yak_store_tests\!` macro in `contract_tests.rs` exercises both
`ReadYakStore` and `WriteYakStore` together. Split it into two macros:
- `read_yak_store_tests\!` — tests for `ReadYakStore` trait
- `write_yak_store_tests\!` — tests for `WriteYakStore` trait

## Why

A `GitTreeReadYakStore` will implement only `ReadYakStore` (reads come
from the git tree; writes go through the event store). The current
macro requires one object implementing both traits, so it cannot be
used to verify a read-only adapter.

## Notes

- The read tests need some way to set up state. They currently call
  `create_yak` / `write_field` (WriteYakStore methods). The read macro
  will need a setup mechanism — either accept a separate writer, or
  accept a closure that populates state.
- The write tests also call ReadYakStore to verify writes worked, so
  they need read access too. The write macro can require both traits.
- Existing test modules for DirectoryStorage and InMemoryStorage should
  invoke both macros and continue to pass.
