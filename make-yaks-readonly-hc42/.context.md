## Goal

Make the `.yaks/` directory and its contents read-only on the filesystem, to model the fact that `.yaks/` is a read-only projection (derived from the event store).

## Acceptance Criteria

- After `yx` writes/updates files in `.yaks/`, the files and directories are set to read-only filesystem permissions
- Users (and tools) cannot accidentally edit `.yaks/` files directly
- `yx` itself can still update `.yaks/` when it needs to (temporarily making files writable, or handling permissions internally)
