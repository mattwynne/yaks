# Goal

Make yx sync read `git config yaks.remote` and use that URL
for fetch/push instead of hardcoded "origin". Fall back to
"origin" when the config key is unset.

# Do This First

This is the foundation — the other two sub-yaks depend on it.

# Files

- Modify: src/adapters/event_store/sync.rs
  - Add resolve_sync_target() that reads git config yaks.remote
  - Update fetch_peer_ref() to use the resolved target
  - Update push command (~line 132) to use the resolved target
- Modify: features/sync.feature — add scenarios under a new
  Rule for configurable remote
- Modify: tests/features/steps.rs — new step def for
  "has configured sync remote to <name>"
- Modify: tests/features/full_stack_world.rs — helper to set
  git config in a clone's repo

# Test Approach

TDD with Cucumber scenarios:
1. Scenario: default behaviour unchanged (sync with origin
   when no config set) — should pass immediately
2. Scenario: sync uses configured URL when yaks.remote is
   set — RED, then implement, then GREEN

# Definition of Done

- yx sync still works with origin (no regression)
- yx sync uses URL from git config yaks.remote when set
- git fetch/push use URL directly (not a named remote)
- dev check passes
