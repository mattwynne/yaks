# Goal
Redesign `yx log` output to be human-readable narrative style,
with commit SHA visible and metadata de-emphasized.

# Type
Feature

# Success Criteria
- Each log entry reads as a natural English sentence with author as subject
- Yak names shown instead of IDs in the narrative
- Yak names and other attributes (states, tags) highlighted with colour/bold, not quotes
- Relative timestamps ("3 days ago") for recent events, absolute date/time for >7 days
- Commit SHA (abbreviated, labelled) shown on each entry
- Event ID shown on each entry
- Metadata (timestamp, event id, sha) visually de-emphasized (grey/dim)
- Horizontal rules separate entries
- Compacted entries handled sensibly

# Design Decisions
- Three-line format: narrative, relative time or date, IDs
- Author is part of the sentence, not a separate header line
- Yak names and attributes highlighted with colour/bold (no quotes)
- Timestamp: relative ("3 days ago") if ≤7 days, otherwise absolute ("2026-02-20 14:30")
- SHA labelled as `sha:`, abbreviated to 7 chars
- Lines 2-3 rendered in dim/grey when color enabled

# Example output (colour indicated in brackets)

```
Matt Wynne added [bold]Fix the Bug[/bold]
3 days ago
event: 019ca7a5  sha: abc1234
────────────────────────────────────────────────────────────────
Matt Wynne started [bold]sync[/bold]
2026-02-20 14:30
event: 88c37e62  sha: def5678
────────────────────────────────────────────────────────────────
Matt Wynne tagged [bold]sync[/bold] with [bold]@foo[/bold], [bold]@bar[/bold]
2 hours ago
event: 96fe76a2  sha: 789abcd
────────────────────────────────────────────────────────────────
```
