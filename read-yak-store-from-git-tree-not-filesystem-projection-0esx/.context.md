# Read YakStore from git tree, not filesystem projection

## What

Implement `ReadYakStore` backed by the git tree instead of the
filesystem `.yaks/` projection. The git tree at `refs/notes/yaks`
already contains all yak data. `read_snapshots_from_tree()` in
`tree.rs` already reads it into `YakSnapshot` structs.

## Gap: YakSnapshot → YakView

The tree gives `Vec<YakSnapshot>`. A `YakView` adds two computed fields:
- `tags`: parsed from the `.tags` custom field  
- `children`: computed by scanning `parent_id` across all yaks

Conversion is a single pass to build a parent_id → children index.

## Keep .yaks/ as write-only projection

Demote `.yaks/` to a human-readable projection the app never reads
from. Projection bugs become cosmetic rather than data-corrupting.

## Approach

1. Split contract tests into separate read/write macros (sub-yak)
2. Create `GitTreeReadYakStore` implementing `ReadYakStore`
3. Drive it out with the read contract tests
4. Wire into Application, run Cucumber for equivalence
5. Switch aggregate to load from git tree
6. Demote DirectoryStorage to write-only
