# Read YakStore from git tree, not filesystem projection

## Problem

The aggregate (`YakMap`) loads its state from the `.yaks/` directory projection via `ReadYakStore`, not from the git event store. ADR 15 documents this trade-off and its risks at length:

- **Projection bugs corrupt the command side.** A bug in `WriteToYakStore` silently corrupts every subsequent command, because the aggregate trusts the projection unconditionally.
- **No version link.** The `.yaks/` directory has no marker indicating which events it reflects. If it drifts from the event store (crash between persist and projection write, bug in reset/compact), there's no way to detect the inconsistency.
- **The projection is critical path.** An entire architectural layer — `WriteToYakStore`, `EventListener` blanket impl, `DirectoryStorage` write path, `clear_all`/rebuild logic — exists solely to maintain a copy of data that already lives in the git tree.

Meanwhile, the git tree at `refs/notes/yaks` already contains everything: each yak is a subtree keyed by `YakId`, containing `.name`, `.state`, `.context.md`, `.parent_id`, `.created.json`, `.tags`, and custom fields. The `read_snapshots_from_tree()` function already reads this into `YakSnapshot` structs.

## Proposed change

Implement `ReadYakStore` backed by the git tree instead of the filesystem. The read path would resolve `refs/notes/yaks` → tip commit → tree, then walk entries to build `YakView` structs — essentially what `read_snapshots_from_tree()` already does.

### Middle ground: keep `.yaks/` as write-only projection

Rather than eliminating `.yaks/` entirely, **demote it to a write-only human-readable projection** that the application never reads from:

- The app reads from git (correctness).
- `.yaks/` is maintained as a convenience for humans and external tools (browsability).
- Projection bugs become cosmetic rather than data-corrupting.
- `yx reset` becomes "rebuild the convenience projection" rather than "recover from corruption."

## Trade-offs

### Gains

- **Eliminates the consistency gap** documented in ADR 15. The read model *is* the event store's current tree — same atomic commit, zero drift window.
- **Projection bugs can't corrupt the command side.** The read path and write path share the same data structure (the git tree).
- **`yx reset` (disk from git) becomes trivial** — just rebuilds the optional human-readable projection.
- **Removes critical-path code** — `WriteToYakStore` is no longer on the read path, so its bugs only affect the convenience projection.

### Costs

- **Performance overhead per read.** Every command resolves the git ref, finds the commit, walks the tree, reads blobs. Currently it's `readdir` + `read_to_string`. Likely negligible for typical yak counts (tens to low hundreds), but measurable.
- **Test architecture rework.** `InMemoryStorage` is used throughout tests as the `ReadYakStore`. Need either: (a) an `InMemoryEventStore` that also implements `ReadYakStore` by deriving state from events, or (b) a git-tree-reading adapter used in tests with `InMemoryEventStore` producing a tree. Contract test macros need updating.
- **Git tree uses YakIds, not slugs.** The git tree keys entries by `make-the-tea-a1b2`, not `make-the-tea`. Direct browsing of the git tree is less human-friendly than `.yaks/`, but that's why we keep `.yaks/` as a side-effect projection.

## Relationship to other yaks and ADRs

- **ADR 15** documents the current trade-off and its risks. This change addresses the core concern.
- **ADR 10** (state reconstruction): `yx reset` simplifies — no longer "recover from projection corruption" but "rebuild convenience projection."
- **ADR 9** (compacted events): Compacted tree reading already works via `read_snapshots_from_tree()`.
- **"spike gix in-memory backend"** yak: if gix provides an in-memory git backend, it could solve the test architecture problem — tests use in-memory git repos with real tree reads, eliminating the need for a separate `InMemoryStorage` entirely.

## Approach

1. Create a `GitYakStore` adapter implementing `ReadYakStore` that reads from the git tree
2. Wire it into `Application` alongside (not replacing) the existing `DirectoryStorage`
3. Run existing Cucumber scenarios against both read paths to verify equivalence
4. Switch the aggregate to load from `GitYakStore`
5. Demote `DirectoryStorage` to write-only projection (remove `ReadYakStore` impl dependency from command side)
6. Update ADR 15 to reflect the new design
