During the first-run onboarding flow, after offering to add .yaks to the project's .gitignore, also offer to add it to the user's global gitignore.

This means they never have to think about it again in any new repo.

Flow:
1. "Add .yaks to this project's .gitignore?" [Y/n] (existing)
2. "Would you also like to add .yaks to your global gitignore so it's ignored in all repos?" [Y/n] (new)

## Detection

Check `git config --global core.excludesFile` for the global gitignore path.

- If set and .yaks already in it → skip the prompt
- If set and .yaks not in it → offer to append
- If not set → offer to create one at ~/.config/git/.gitignore and configure git

## Manual steps (what the feature automates)

If global gitignore is already configured:
```bash
git config --global core.excludesFile
# e.g. ~/.config/git/.gitignore
echo ".yaks" >> ~/.config/git/.gitignore
```

If not configured yet:
```bash
mkdir -p ~/.config/git
echo ".yaks" >> ~/.config/git/.gitignore
git config --global core.excludesFile ~/.config/git/.gitignore
```
