# Goal
Design the command/interface Matt will use to cut releases with minimal thinking.

# Preferred shape
A single command such as:

```bash
dev release 0.2.0
```

or:

```bash
bin/release 0.2.0
```

# Behaviour
The command should:
- refuse if not on `main`
- refuse if working tree is dirty
- fetch and verify local `main` is up to date with origin
- run `dev check`
- update `Cargo.toml` package version
- update `Cargo.lock`
- update `CHANGELOG.md` by promoting `[Unreleased]` to `[x.y.z] - YYYY-MM-DD`
- create a fresh empty `[Unreleased]` section
- validate changelog has content for the release
- commit `Release vX.Y.Z`
- create annotated tag `vX.Y.Z`
- either push commit+tag with confirmation or print the exact push command

# Open questions
- Should the command push automatically after confirmation, or only prepare the commit/tag?
- Should it infer patch/minor versions, e.g. `dev release minor`, or require explicit version initially?

# Recommendation
Start with explicit version and confirmation before push. Add inference later if it still feels useful.
