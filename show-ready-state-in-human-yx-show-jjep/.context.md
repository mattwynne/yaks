# Goal

Show a yak's derived readiness in the human-readable `yx show <yak>` output, not only in JSON.

# Type

Feature

# Rationale

Readiness is a core concept distinct from workflow state. Agents can inspect `yx show --format json`, but humans using plain `yx show` should also see whether a yak is ready and why not.

# Success Criteria

- Plain `yx show <yak>` displays readiness for the selected yak.
- If ready, show a concise positive indication, e.g. `Ready: yes`.
- If not ready, show `Ready: no` plus human-readable reasons, e.g. `state is wip`, `has incomplete children: parent/child`, or blocker reasons.
- JSON `yx show --format json` remains unchanged.
- Existing layout remains readable and not noisy.
