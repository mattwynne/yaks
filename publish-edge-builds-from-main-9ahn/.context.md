# Goal
Keep an automated unstable channel for dogfooding builds from `main`, but call it `edge` rather than `latest`.

# Desired behaviour
- Pushes to `main` publish/update GitHub prerelease tag `edge`.
- Edge release body clearly says it is unstable and built from main.
- Edge artifacts use same platform artifact names as stable releases.
- Installer can opt into this channel with something like:

```bash
YX_CHANNEL=edge curl -fsSL https://raw.githubusercontent.com/mattwynne/yaks/main/install.sh | bash
```

# Implementation options
1. Split workflows:
   - `release.yml` for stable version tags
   - `edge.yml` for main branch prereleases
2. Keep one workflow with conditional logic.

# Recommendation
Split workflows for clarity. Stable release failures and edge failures should be easy to understand independently.

# Migration
The existing rolling `latest` prerelease should either be abandoned or replaced by `edge`. Avoid using `latest` for unstable releases because users expect latest to mean latest stable.
