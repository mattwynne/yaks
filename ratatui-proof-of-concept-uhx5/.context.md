# Goal
Prove ratatui works for our use case: a TuiDisplay adapter that
implements DisplayPort using ratatui widgets, rendering inline
to a TTY.

# Key Discovery (from spike)
- CrosstermBackend accepts any Write, but output is raw escape
  sequences — not useful for testing
- Viewport::Inline needs a real TTY (fails with Vec<u8>)
- TestBackend captures Buffer of styled cells — great for testing
- Direct Buffer::empty + Widget::render works for unit testing
  widgets without a Terminal
- buffer_to_string() helper extracts text for contains() assertions

# Architecture
- ConsoleDisplay stays as-is (plain text, Write-based, non-TTY)
- NEW TuiDisplay implements DisplayPort using ratatui
- Route at startup: TTY → TuiDisplay, piped → ConsoleDisplay
- Tests for TuiDisplay use TestBackend + buffer_to_string()
- Tests for ConsoleDisplay unchanged

# Definition of Done
- ratatui + crossterm added as dependencies
- TuiDisplay struct implements DisplayPort (at least one method)
- Tested via TestBackend with buffer_to_string() assertions
- ConsoleDisplay tests still pass unchanged
- TTY routing picks TuiDisplay when appropriate

# Known Knowns

- buffer_to_string() extracts text, cell.fg/modifier for styles
- Viewport::Inline(n) for production TTY rendering
- NO_COLOR and piped-output → fall back to ConsoleDisplay
