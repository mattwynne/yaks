# Goal
Prove ratatui works for our use case: inline rendering of styled
output in a CLI that writes to stdout and exits (not a full-screen
TUI app).

# Key Discovery
Ratatui has `Viewport::Inline(height)` — renders a fixed-height
viewport inline with terminal output, no alternate screen needed.
Perfect for CLI tools.

# Definition of Done
- ratatui added as dependency in Cargo.toml
- One existing display method re-rendered via ratatui (e.g. the
  header box from `yx show`)
- Existing Cucumber tests still pass (output may change cosmetically)
- NO_COLOR and piped-output modes still work
- InProcessWorld tests unaffected (they use TestBuffer with color off)

# Known Knowns
- Use `Viewport::Inline(n)` with `Terminal::with_options`
- ConsoleDisplay already detects TTY and terminal width
- DisplayPort trait means we can swap rendering per-method
- ratatui needs a backend — crossterm is the standard choice
- Can introduce ratatui incrementally, one method at a time

# Known Unknowns
- Does Viewport::Inline play well with our TestBuffer approach?
- Performance overhead of ratatui vs raw ANSI writes?
- Does crossterm conflict with our existing terminal_size crate?
- Can we render a ratatui Frame into a String for testing?
