# Goal
Change release automation so stable releases are published from version tags instead of only updating a rolling `latest` prerelease.

# Desired behaviour
- Trigger on tags matching `v*`.
- Build release binaries for supported platforms.
- Publish a non-prerelease GitHub Release for that tag.
- Release title should be the tag, e.g. `v0.2.0`.
- Release body should come from the matching `CHANGELOG.md` section.
- Artifacts should keep the existing names:
  - `yx-linux-x86_64.zip`
  - `yx-macos-aarch64.zip`
  - `install.sh`

# Validation before publishing
- Tag version matches `Cargo.toml` package version.
- `CHANGELOG.md` contains a section for the version.
- Release notes extraction produced non-empty notes.

# Notes
Current `.github/workflows/release.yml` publishes to tag `latest` and marks it prerelease. That should become stable-tag publishing, or be split so stable and edge are separate workflows.
