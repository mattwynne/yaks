## Problem

`src/domain/slug.rs:182` uses `std::collections::hash_map::DefaultHasher` to generate the 4-char hash suffix for yak slugs (e.g. `my-yak-a1b2`). While it currently uses SipHash with known keys (0, 0), `DefaultHasher` is **not contractually stable** across Rust versions.

If a Rust update changes the default hasher, existing yak IDs would no longer be reproducible from the same inputs — though in practice IDs are stored, not recomputed, so the risk is mainly for tests.

### Fix

Replace with a stable hash like FNV, xxHash, or just pin to `SipHasher` directly.

### Impact

Low — defensive improvement.
