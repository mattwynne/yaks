# Goal
Provide two project-specific contributor workflows usable without Pi or Superpowers.

# Files
- Create/consolidate .agents/skills/prepare/SKILL.md from useful preparing-a-yak and plugin prepare guidance.
- Create/consolidate .agents/skills/work/SKILL.md from useful yak-worktree-workflow and plugin work guidance.
- Reuse retained BDD discovery and formulation skills through valid relative references.
- Follow AGENTS.md, CONTRIBUTING.md, src/README.md, and relevant CLI/architecture guidance.

# Prepare workflow
Read existing yak context and relevant code. Discuss scope and material design decisions with the human. Use example mapping to discover behavioral rules, concrete examples, and open questions. Use BDD formulation to express agreed acceptance examples. Store agreed context on yaks; use CLI help for generic mapping. Plans live in the yak hierarchy, not a required plan field.

# Work workflow
Claim the selected yak, use an isolated worktree (reuse an appropriate existing one), implement with one-test-at-a-time TDD, verify with focused checks and dev check, commit, merge with dev merge, mark done, and clean up safely. Delegation is optional; do not require Pi function names, agent profiles, or a vendor-specific subagent schema.

# Definition of done
- Skill names, descriptions, and introductions explicitly say they are for contributors maintaining Yaks itself.
- Preserve example mapping and BDD formulation as deliberate project practices.
- Both workflows work with Claude's ordinary available tools without Pi or Superpowers.
- Supporting project guidance is linked rather than duplicated.
- Concrete commands and links are valid; verification follows repository policy.
