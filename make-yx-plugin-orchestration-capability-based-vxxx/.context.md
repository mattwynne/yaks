# Goal
Make the `yx` Claude plugin's map/prepare/work workflows usable when the host agent's delegation API differs from Pi's schema.

# Files
- Modify: `plugins/yx/skills/work/SKILL.md`
- Modify as needed: `plugins/yx/skills/map/SKILL.md`
- Modify as needed: `plugins/yx/skills/prepare/SKILL.md`
- Modify if metadata clarification is needed: `plugins/yx/.claude-plugin/plugin.json`
- Add focused plugin-skill checks under `tests/shellspec/`

# Design
The plugin may be Claude-focused, but its written workflow must express capabilities and outcomes rather than hard-code Pi's `subagent({agent, task, cwd})` or parallel `tasks` signature. If delegation exists, tell the host to use its available agent facility in the prepared worktree. If it does not, allow the current agent to perform the same isolated-worktree workflow directly. Preserve review, verification, and main-branch safety.

# Test Approach
Add one failing test for each mandatory Pi-only API shape, then replace it with host-neutral instructions while keeping concrete yx and dev commands testable.

# Definition of Done
- Plugin skills contain no mandatory Pi-only function signatures.
- Claude Code can invoke the plugin skills and translate orchestration into its native agent facilities.
- A host without delegation can still complete work safely in an isolated worktree.
- Main-branch protection is expressed as workflow instructions and repository commands, not assumed to exist via Pi's `protect-main` extension.
- Focused tests pass.
