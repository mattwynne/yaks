# Goal
Resolve GitHub issue #21 so contributors can discover and use the repository's skills without requiring Matt's Pi extensions or Superpowers installation.

# Type
Chore with user-visible contributor workflow changes.

# Scope
- Preserve `skills/` as the canonical shared skill directory and the tracked `.claude/skills -> ../skills` discovery symlink.
- Cover both shared skills in `skills/` and the Claude plugin skills in `plugins/yx/skills/`.
- Correct invalid yx commands, broken resource paths, contradictory guidance, and merge instructions.
- Make runtime-specific orchestration optional; every workflow must have a baseline using documented repository tools and ordinary agent capabilities.
- Add regression coverage and contributor-facing documentation for discovery and portability.

# Design Decisions
- Support multiple capable coding-agent runtimes rather than declaring Pi mandatory.
- Use yx 0.6.1 syntax as the command source of truth.
- Keep one canonical copy of each shared skill; do not duplicate SKILL.md files under `.claude/`.
- Follow AGENTS.md: TDD one test at a time, `dev check`, and `dev merge`.
- Add a user-focused CHANGELOG.md entry under Unreleased.

# Definition of Done
- Claude Code project sessions can discover all shared skills through the existing directory symlink.
- All checked-in skill commands and relative references are valid against the current repository.
- Shared workflows do not require undeclared Pi, Superpowers, or agent-specific tool schemas.
- The yx plugin explains or provides portable fallbacks where orchestration APIs differ.
- Automated checks catch regressions in discovery, command syntax, resource paths, and prohibited hard dependencies.
- CONTRIBUTING.md documents the supported skill-loading and portability contract.
- Focused tests and `dev check` pass.
