# Prevent broken code reaching main

## Background

Commit c26343b3 ("Replace YAK_PATH with YX_ROOT") landed on main with
5 failing tests. Investigation showed it was merged via `git merge`
of a manually-created branch `yx-root` (not via `dev start` / `dev merge`),
likely by an AI agent (Claude Code) that didn't follow the workflow.

## Two changes

### 1. Strengthen CLAUDE.md with explicit prohibitions

Add a section making the rules unmissable for agents:

```markdown
## CRITICAL: Branch and Merge Rules

**NEVER push directly to main.** All changes reach main through
`dev merge <branch>` only.

**NEVER create branches manually.** Use `dev start "<yak-name>"`
which creates the worktree and branch with the correct naming.

**NEVER use `git merge`, `git push`, or `--no-verify`.** The only
merge path is `dev merge`, which runs `dev check` first.

If you find yourself wanting to bypass these rules, STOP and ask
the human.
```

### 2. Remove the `.last-checked` shortcut from `dev merge`

In `bin/dev`, the `check()` function starts with:

```bash
if .githooks/verify-checks 2>/dev/null; then
    echo "✅ Already verified — nothing changed since last check"
    return 0
fi
```

This timestamp-based shortcut is fine for git hooks (fast feedback
during development), but `dev merge` is the gate — it should NEVER
short-circuit.

Fix: when `check` is called from within `merge`, always run the
full suite. Simplest approach: set an env var in `merge()` before
calling `check`, and have `check` skip the shortcut when that var
is set.

```bash
# In merge():
FORCE_CHECK=1 check

# In check():
if [ -z "${FORCE_CHECK:-}" ] && .githooks/verify-checks 2>/dev/null; then
    echo "✅ Already verified — nothing changed since last check"
    return 0
fi
```

## Definition of Done

- CLAUDE.md has explicit branch/merge prohibitions
- `dev merge` always runs the full `dev check` (no shortcut)
- Existing `dev check` shortcut still works for standalone use and git hooks
- `dev check` passes
