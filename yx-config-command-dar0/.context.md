# Spec: yx config command

## Goal
Add user-level configuration to yx, stored in ~/.config/yaks/config.toml (respects XDG_CONFIG_HOME).

## Scope
- In scope: `yx config set <key> <value>`, `yx config get <key>`, `yx config list`
- Out of scope: project-level config, config file migration, complex nested values

## Key Decisions
- TOML format (Rust ecosystem standard, human-editable)
- Location: $XDG_CONFIG_HOME/yaks/config.toml or ~/.config/yaks/config.toml
- New port: UserConfigPort (hexagonal architecture, swappable in tests)
- First config key: `show-claude-plugin-hint` (default true, set false to suppress banner)

## Why
This is the first user-level state in yx. Needed to support the CLAUDECODE plugin banner (parent yak) — users need a way to suppress it. Also opens the door for future user preferences.

## Acceptance Criteria
- [ ] `yx config set show-claude-plugin-hint false` writes to ~/.config/yaks/config.toml
- [ ] `yx config get show-claude-plugin-hint` returns the value (or default if unset)
- [ ] `yx config list` shows all config with current values
- [ ] Respects XDG_CONFIG_HOME if set
- [ ] Creates config dir and file if they don't exist
- [ ] UserConfigPort trait allows in-memory adapter for testing
- [ ] Cucumber acceptance tests covering set/get/list
