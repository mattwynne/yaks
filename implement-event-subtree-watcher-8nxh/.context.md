# Goal
Implement the shared event-watching logic that detects new events after startup and filters them against a dynamic yak subtree.

# Files
- Create: `src/application/event_watcher.rs`
- Modify: `src/application/mod.rs` to export the watcher use case/helpers
- Modify: `src/domain/ports/event_store.rs` if a more explicit read/tail abstraction is needed
- Modify: `src/adapters/event_store/git.rs` and `src/adapters/event_store/memory.rs` only if the event reader needs refresh/tail support
- Test: Rust unit tests in `src/application/event_watcher.rs`

# Test Approach
- Unit-test filtering for selected yak, descendants, ancestors, unrelated yaks, and nested descendants.
- Unit-test dynamic subtree changes:
  - move into subtree surfaces the move event and includes later events
  - move out of subtree surfaces the move event and excludes later events
  - removal of a watched descendant surfaces the removal event
- Unit-test that historical events present before watcher startup are ignored.
- Prefer an injectable clock/sleep/poll source so unit tests do not use arbitrary sleeps.

# Definition of Done
- Shared watcher logic can be reused by both `events watch` and `events wait-for-next`.
- Watch starts from the current end of the event stream, not from historical events.
- Filtering is based on the current projected tree/read model and handles boundary move/remove events as specified.
- Tests cover filtering and dynamic membership without flaky timing.
- No public CLI command is required in this slice.
