# Goal
Implement the shared event-watching logic that subscribes to global event batches and filters them against a dynamic yak subtree.

# Files
- Create: `src/application/event_watcher.rs`
- Create/modify: `src/domain/ports/global_event_bus.rs` or an application/infrastructure port module for `GlobalEventBus`
- Modify: `src/domain/ports/mod.rs` if the port lives with existing ports
- Create/modify: `src/adapters/event_store/global_event_bus.rs` or similar git-backed adapter
- Modify: `src/adapters/event_store/mod.rs` to export the adapter
- Modify: `src/application/mod.rs` to export watcher use case/helpers
- Modify: existing `EventBus` naming only if this slice owns the local/global terminology cleanup; otherwise leave a TODO/follow-up
- Test: Rust unit tests in `src/application/event_watcher.rs` and adapter-focused tests where practical

# Architecture
- Use a `GlobalEventBus` abstraction, not direct polling inside the use case.
- `GlobalEventBus` should represent cross-process durable event observation:
  - subscribe from now
  - wait for next committed event batch with optional timeout
  - return `YakEvent` batches or equivalent
- The git-backed implementation should use filesystem watching as the primary trigger and polling as fallback:
  - watch `.git/refs/notes/yaks`, `.git/packed-refs`, and parent directories needed for git lockfile/rename updates
  - keep a cursor from subscription start
  - reread events via `EventStoreReader` after a change notification
- The existing in-process `EventBus` is local-only projection dispatch and should remain separate from `GlobalEventBus`.
- This seam is intended to support future live TUI subscriptions as well as `yx events`.

# Test Approach
- Unit-test filtering for selected yak, descendants, ancestors, unrelated yaks, and nested descendants using a fake `GlobalEventBus`.
- Unit-test dynamic subtree changes:
  - move into subtree surfaces the move event and includes later events
  - move out of subtree surfaces the move event and excludes later events
  - removal of a watched descendant surfaces the removal event
- Unit-test that historical events present before watcher startup are ignored by subscription/cursor semantics.
- Unit-test timeout outcomes using a fake bus; do not rely on arbitrary sleeps.

# Definition of Done
- Shared watcher logic can be reused by both `events watch` and `events wait-for-next`.
- Watch starts from the global subscription point, not from historical events.
- Filtering is based on current projected tree/read model and handles boundary move/remove events as specified.
- Tests cover filtering and dynamic membership without flaky timing.
- No public CLI command is required in this slice.
