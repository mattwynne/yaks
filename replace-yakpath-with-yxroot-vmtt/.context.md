# Replace YAK_PATH with YX_ROOT

## Problem

yx currently uses two env vars for non-standard environments:

- `YAK_PATH` — overrides where the `.yaks` directory lives
- `YX_SKIP_GIT_CHECKS` — disables git repo requirement entirely

This creates two problems:

1. **Nested git repos break yx.** When a user cd's into a sub-repo
   inside a workspace, `discover_git_root()` finds the inner repo.
   Write operations fail because the inner repo has no `.yaks` and
   its git notes are wrong. There's no way to say "use this outer
   repo as root" — `YAK_PATH` only overrides the projection path,
   not the git root used for event storage, checks, and migration.

2. **Fullstack tests don't test the real event store.** The test
   harness sets `YAK_PATH` + `YX_SKIP_GIT_CHECKS`, which swaps in
   a `NoOpEventStore`. Events are silently discarded. The tests
   exercise CLI -> use case -> directory projection, but never
   touch git notes. Bugs in event persistence, migration, or
   round-tripping through `refs/notes/yaks` go undetected.

## Design

### Single env var: `YX_ROOT`

Replace `YAK_PATH` with `YX_ROOT`. It points to the **repo root**
(not the `.yaks` directory). When set:

- `discover_git_root()` validates `$YX_ROOT` is a git repo using
  `git2::Repository::open($YX_ROOT)`. If not, it errors with:
  "YX_ROOT does not point to a git repository: <path>"
- `.yaks` path is derived as `$YX_ROOT/.yaks`
- The git event store uses `$YX_ROOT` for `refs/notes/yaks`
- Git checks (e.g. "is `.yaks` gitignored?") run against `$YX_ROOT`

When not set, behaviour is unchanged: `git2::Repository::discover(".")`
walks up from cwd. The existing relative-path fallback
(`PathBuf::from(".yaks")`) is removed — if git discovery fails and
`YX_ROOT` is unset, yx errors with "not in a git repository".

### Behavioural rules

- **`YX_ROOT` set, valid git repo:** use it as root, skip discovery
- **`YX_ROOT` set, not a git repo:** error with clear message
- **`YX_ROOT` unset:** discover via `git2` as today
- **`YX_SKIP_GIT_CHECKS` set:** bypass all git requirements
  (orthogonal to `YX_ROOT`)

### `YAK_PATH` is removed

No backwards-compatibility shim. All references replaced with
`YX_ROOT`. The `.yaks` directory always lives at `<repo-root>/.yaks`.

**Semantic shift:** `YAK_PATH` pointed to the `.yaks` directory
itself (e.g. `/workspace/.yaks`). `YX_ROOT` points to its parent,
the repo root (e.g. `/workspace`). Update paths accordingly.

### `YX_SKIP_GIT_CHECKS` stays

It keeps its current purpose: run yx completely outside a git repo
(mutation testing CI, quick demos with `NoOpEventStore`). It's
orthogonal to `YX_ROOT`.

### Updated feature scenarios

The `git_checks.feature` rules become:

- **Must be run inside a git repository** — unchanged
- **yx auto-discovers the git repo root** — unchanged
- **YX_ROOT overrides git root detection** — when `YX_ROOT` points
  to a valid git repo with `.yaks` gitignored, yx uses it
  regardless of cwd (including from nested sub-repos)
- **YX_ROOT must point to a git repo** — setting `YX_ROOT` to a
  non-git directory errors
- **YX_SKIP_GIT_CHECKS bypasses all git requirements** — unchanged

The old "YAK_PATH takes precedence" and "Git is required even when
YAK_PATH is set" rules are replaced by the `YX_ROOT` rules above.

### Fullstack tests use real git repos

The test harness changes from:

```rust
.env("YAK_PATH", &self.repo_path)
.env("YX_SKIP_GIT_CHECKS", "1")
```

to:

```rust
.env("YX_ROOT", &self.repo_path)
```

The `new()` constructor inits a real git repo in the temp directory
(with `.yaks` gitignored). Tests now exercise the full event store
path: command -> event -> git notes -> projection.

Tests that specifically test "no git repo" behaviour keep using
`YX_SKIP_GIT_CHECKS`.

**Test harness scope:** there are ~30 call sites in
`full_stack_world.rs` setting `YAK_PATH`/`YX_SKIP_GIT_CHECKS`,
spread across individual step functions and `run_in_*` methods.
Since `repo_path` will now be a real git repo, several fields on
`FullStackWorld` (`git_repo`, `explicit_yak_path`) and the
`run_in_override_dir` variants may become redundant and can be
collapsed into the standard `run_yx` path.

## Scope

### In scope

- Rename `YAK_PATH` to `YX_ROOT` in `src/main.rs`
- Update `discover_git_root()` to check `YX_ROOT` first (with
  validation)
- Remove the `.yaks` relative-path fallback
- Update `FullStackWorld::new()` to init a git repo in the temp dir
- Replace all `YAK_PATH` + `YX_SKIP_GIT_CHECKS` usage in test
  harness with `YX_ROOT`
- Simplify test harness where fields/methods become redundant
- Update feature files (`git_checks.feature`)
- Update CLAUDE.md, skills, and docs referencing `YAK_PATH`
- Close PR #6 (superseded by this change)

### Out of scope

- `YAKS_WRITE_PATH` or any separate projection-path override (YAGNI)
- Changes to `YX_SKIP_GIT_CHECKS` behaviour
- Changes to the InProcessWorld test path

## Migration

There are no known external consumers of `YAK_PATH` beyond this repo
and the yakthang companion repo (PR #7). Both update together.
