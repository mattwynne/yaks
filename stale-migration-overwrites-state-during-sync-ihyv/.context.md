## Bug: Stale migration overwrites state during sync

### Observed behaviour
On a machine with an old binary (old schema version) and stale local
yak state, running `yx sync` after upgrading the binary:
1. Migration runs first (main.rs:633), creates a Migrated event
   with stale snapshots and a current timestamp
2. Sync merges the Migrated event with origin's correct events
3. Migrated event sorts LAST (newest timestamp) in the merge
4. During replay, the Migrated commit becomes the tip of the ref
5. get_all_events() hits the Migrated boundary first, reads stale
   snapshots, stops — all real events below it are invisible

Result: entire yak state replaced with stale data from the old machine.

### Root cause
Migration runs before sync in main.rs:633. compact_ref() in
migration.rs:173 creates a "Migrated" boundary event from whatever
state is currently in the local tree. If local state is stale, the
Migrated event captures stale state.

The merge code in mod.rs:86-88 only handles YakEvent::Compacted for
orphan reordering. Migrated events pass through as ordinary events,
sorted by timestamp.

### Key code locations
- migration.rs:173 compact_ref() — creates the Migrated commit
- main.rs:633 — migration runs before any command
- sync.rs:67 sync_with_remote() — the sync flow
- mod.rs:53 merge_event_streams() — the merge logic
- git.rs:386 get_all_events() — walks history, stops at boundaries
- adapters/event_store/tree.rs — read_snapshots_from_tree()

### Relevant ADRs
- ADR 0009: Compacted event design (orphan reordering for Compacted)
- ADR 0011: Schema versioning and sync compatibility
- ADR 0012: Compact after migration to hide pre-migration history
- ADR 0020: UUID for migration compaction events

### Reproduction test
A @fullstack @wip cucumber test exists in sync.feature:
"Bob's stale local yaks don't replace Alice's after migration
and sync" — with step definition v1_yak_in_repo in steps.rs.
Committed to main.

### Chosen fix: Lazy migration, no boundary events

**Eliminate the Migrated boundary event entirely.** Instead of
rewriting history and creating a checkpoint, teach the reader
to upgrade old-format trees on the fly.

#### Design

1. **Migration upgrades the tip tree only.** On startup, if the
   tip tree's .schema-version < CURRENT, run migrations to
   transform the tip tree to current format. Commit the upgraded
   tree (so new appends are in current format). Do NOT create a
   Migrated/Compacted boundary event.

2. **get_all_events() migrates old trees lazily.** When walking
   history backwards, if a commit's tree has an older schema
   version, apply the migration chain to that tree before reading
   snapshots/fields from it. Each tree already carries
   .schema-version so the reader knows exactly which migrations
   to apply.

3. **No compaction after migration.** Migration and compaction
   are separate concerns. Migration upgrades the tip so new
   writes are correct. Compaction remains a user-triggered
   performance optimisation (yx compact). The projection rebuild
   on startup (needs_projection_reset in main.rs) handles the
   "first run after upgrade" read cost.

4. **Remove YakEvent::Migrated entirely.** It's no longer
   produced or consumed. The merge code no longer needs to
   handle it. Existing Migrated commits in the wild are handled
   by get_all_events() — they still work as boundaries for
   backward compatibility, but no new ones are created.

5. **Sync is unaffected.** No boundary events means nothing to
   corrupt during sync. The peer ref migration (sync.rs:106)
   still migrates the peer's tip tree before reading.

#### Why this works
- Kills the bug at the root — no Migrated event means no stale
  snapshot to overwrite correct state during sync
- ADR 0012's concern about fallback code accumulation is
  addressed differently: the migration chain IS the fallback,
  invoked at read time instead of write time. Same code, just
  called lazily.
- Compaction with its existing merge semantics (orphan
  reordering etc.) remains the only boundary event type

#### Implementation plan
1. Make get_all_events() detect .schema-version on each tree
   and apply migrations lazily when reading old-format trees
2. Remove compact_ref() call from migration.rs ensure_schema()
3. Remove YakEvent::Migrated variant (or keep for backward
   compat reading only — existing Migrated commits in the wild
   should still work as read boundaries)
4. Update merge_event_streams() to strip any Migrated events
   encountered from old stores
5. Get the @wip cucumber test green
6. Write an ADR superseding ADR 0012
7. Run full test suite + mutation testing
