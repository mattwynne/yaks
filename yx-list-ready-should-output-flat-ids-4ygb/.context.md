# Goal

Make `yx list --ready` useful for agents by outputting a flat list of ready yak IDs instead of a pruned tree with broken connectors.

# Type

Feature / UX fix

# Problem

Current `yx list --ready` renders a partial tree. Because ancestors are omitted, connector/prefix rendering becomes confusing and visually broken. It also makes the output harder for agents to consume.

# Desired Behaviour

- `yx list --ready` should output a flat list of ready yak IDs, one per line.
- No tree connectors, no context, no ancestors.
- Ready means derived readiness is true: todo, unblocked, no incomplete children.
- If humans need names too, consider adding/keeping another format, but the default ready output should prioritize agent consumption.

# Questions

- Should `yx list --ready` always be ids-only, or should this be `yx list --ready --format ids` with the pretty default fixed separately?
- Should the flat list include names alongside IDs, e.g. `<id>\t<name>`, or IDs only?

# Acceptance Notes

Current broken example includes orphaned connector prefixes such as `│  ╰─` without visible parents. The fix should remove that class of output entirely for `--ready`.
