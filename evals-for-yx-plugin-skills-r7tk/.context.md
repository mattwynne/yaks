Evals to verify that Claude, with the yx plugin installed, behaves well for first-time and ongoing users.

Scenarios to cover:

## Skill discovery
- User says "help me plan this refactoring" → Claude uses /yx:map
- User says "what should I work on next?" → Claude checks yx ls
- User says "this task is too big" → Claude uses /yx:prepare
- User says "break down this feature" → Claude uses /yx:map or /yx:prepare

## Yak-shaving discipline
- Agent is mid-task and discovers prerequisite work → suggests capturing it as a yak rather than diving in
- Agent notices a tangential improvement → offers to capture as a yak, stays on current task
- Agent discovers a blocker → captures it as a yak, surfaces to human

## CLI competence
- Agent uses correct yx syntax (not guessed/hallucinated flags)
- Agent handles first-run gitignore error gracefully
- Agent can read yak state, add context, tag, change state

## Session priming
- Agent knows current work state at start of session (once yx prime exists)

This yak will drive out what combination of skills, reference docs, and always-on context the plugin needs.
