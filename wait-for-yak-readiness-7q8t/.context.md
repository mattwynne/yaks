Goal: let one agent wait until a yak being worked on by another agent becomes ready.

Context:
- Current `yx events` streams committed domain events only.
- Readiness is derived, not stored workflow state.
- The desired capability is probably a state/projection wait, e.g. `yx events wait-until <yak> ready`, rather than a new domain event.
- The waiter should wake when any committed event could change readiness for the watched yak, then recompute readiness from the in-memory/read-model projection.
- Must preserve stdout purity if emitting machine-readable output, and report timeout/errors on stderr.

Questions:
- Should this be a new `events wait-until` command or part of `wait-for-next`?
- Should it wait for `ready == true` only, or support other predicates like `done`, `not-ready`, `wip`?
- What should the output be: the triggering event, the yak readiness snapshot, or both?
