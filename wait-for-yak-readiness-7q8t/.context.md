# Goal

Let one agent wait until a yak being worked on elsewhere becomes ready, so multi-agent workflows can coordinate through the yak map.

# Type

Feature

# Success Criteria

- Add a condition-waiting command for derived readiness, tentatively `yx events wait-until <yak> ready [--timeout <duration>]`.
- `<yak>` is resolved using the same fuzzy matching rules as other yak-name commands.
- If the yak is already ready when the command starts, the command exits `0` immediately.
- If the yak is not ready, the command watches committed events from now onward and recomputes readiness after relevant changes.
- When the yak becomes ready, the command emits the same JSON shape as `yx show <yak> --format json` and exits `0`.
- The emitted JSON includes readiness information (`readiness.ready` and readiness reasons) so the waiting agent can verify the condition and inspect context.
- With `--timeout`, the command exits non-zero if the yak does not become ready before the timeout.
- On timeout or errors, stdout is empty/pure machine output and diagnostics go to stderr.
- Readiness remains derived; do not introduce a new `ReadinessChanged` domain event.
- Existing `yx events watch` and `yx events wait-for-next` domain-event behaviour remains unchanged.

# Design Decisions

- Use a separate `wait-until` command rather than overloading `wait-for-next`.
  - `wait-for-next` waits for a domain event.
  - `wait-until` waits for a projected condition to become true.
- Put the command under `events` for v1 because it is implemented by watching the event stream, even though readiness itself is not a domain event.
- V1 supports only the `ready` predicate.
- Output should reuse the `yx show <yak> --format json` schema rather than inventing a readiness-specific envelope.
- The command should recompute readiness from an in-memory projection/read model after relevant committed events.

# Notes

Human-readable `yx show` may or may not display readiness depending on the installed binary/version. The contract for this yak is the JSON show schema used by agents/scripts, not the human pretty display.
