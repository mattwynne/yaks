# Status

Superseded / no longer valid as originally written.

# Current Behaviour

`blocked` is no longer a workflow state. Valid workflow states are now:

- `todo`
- `wip`
- `done`

Blocking is represented separately as readiness/availability via blockers:

- manual/external blocker: `yx blocker add <yak> --reason "waiting for ..."`
- yak-to-yak blocker: `yx blocker add <yak> --by <blocker> [--reason ...]`

# Remaining Help Work

If this yak is kept, repurpose it to verify help/error text reflects the new model:

- `yx state --help` and invalid-state errors list only `todo`, `wip`, `done`.
- Trying `yx state <yak> blocked` fails clearly.
- The error suggests using `yx blocker add <yak> --reason ...` for blocked work.
- `yx blocker --help` explains manual and yak-to-yak blockers.

Much of this may already be covered by `separate workflow state from blocked availability`; review before implementing anything here.
