Split the single yx crate into separate crates (e.g. yx-domain, yx-adapters, yx-app) to make dependency boundaries explicit at the compiler level. Currently the hexagonal architecture is enforced by convention — adapter code could import domain types it shouldn't, and main.rs has access to everything. Separate crates would make illegal dependencies a compile error.

This subsumes "move Cli into library crate" — Cli would naturally land in yx-adapters.

Blocked by: nothing, but should be done when there's appetite for a larger refactor.
