## Goal

Introduce a changelog and proper versioned releases with maximum automation.

## Current State

- Version 0.1.0 hardcoded in Cargo.toml and flake.nix
- Only git tag: `latest` (moving tag, pre-release)
- No CHANGELOG.md
- Commit style: imperative ("Add X", "Fix Y") — not conventional commits
- release.yml publishes a `latest` pre-release on every push to main
- Distribution: install.sh + GitHub release zips (Linux x86_64, macOS aarch64)

## Approach

Use git-cliff (not release-plz) because:
- Works with existing imperative commit style (no need for conventional commits)
- Fits the `dev` script culture better than PR-based release-plz
- Configurable grouping via regex patterns on commit messages

## Phases

1. Foundation: git-cliff + cliff.toml + initial CHANGELOG.md + `dev changelog`
2. Release command: `dev release [major|minor|patch]` that bumps versions,
   generates changelog, creates tag, pushes
3. CI: tag-triggered release workflow + separate `latest` continuous build +
   version-aware install.sh
4. Polish: dry-run support, version consistency hook
