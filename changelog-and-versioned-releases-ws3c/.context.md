## Goal

Introduce a changelog and proper versioned releases with maximum automation.

## Current Status (updated 2026-05-16)

Most of this landed, but the yak map had drifted from the code. The implementation chose a maintained changelog + release helper scripts rather than `git-cliff`.

Done in repo:

- `CHANGELOG.md` exists with `[Unreleased]` and `0.2.0` sections.
- `bin/release VERSION` prepares a release commit, promotes the changelog, bumps `Cargo.toml` / `Cargo.lock`, creates an annotated `vX.Y.Z` tag, and pushes `main` + tag.
- `bin/dev release VERSION` wraps `bin/release`.
- `bin/changelog-section VERSION` extracts release notes.
- `bin/check-release VERSION` validates version metadata, lockfile consistency, changelog notes, and `yx --version` when a built binary is available.
- `.github/workflows/release.yml` publishes stable releases from `vX.Y.Z` tags.
- `.github/workflows/edge.yml` publishes a mutable `edge` prerelease from `main`.
- `install.sh` defaults to latest stable, supports `YX_VERSION`, and supports `YX_CHANNEL=edge`.

Superseded / not part of landed approach:

- `git-cliff`
- `cliff.toml`
- `dev changelog`

Still worth deciding / doing:

- `flake.nix` still appears to carry `version = "0.1.0"` while `Cargo.toml` is `0.2.0`; either include it in release bumps or remove/version it differently.
- Dry-run support for `bin/release`.
- A version consistency hook/check if we want this enforced outside release time.
