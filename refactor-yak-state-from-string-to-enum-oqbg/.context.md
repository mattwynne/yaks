# Goal
Replace `String` yak state with a `YakState` enum (`Todo`, `Wip`, `Done`) throughout the codebase.

# Type
Refactoring

# Motivation
Mutant survived: `replace && with || in YakMap::update_state` (line 277).
The mutant survives because state transitions are detected via string comparisons
and ad-hoc boolean flags. With an enum, transition logic becomes pattern matching
on typed variants — making the `&&`→`||` mutation a compile error, not a runtime subtlety.

This is primitive obsession: using `String` where a domain type would constrain meaning.

# Current Design
- `yak.state` is a `String` ("todo", "wip", "done")
- `validate_state()` checks the string is one of the three valid values
- Transition detection uses: `old_state == "todo" && state != "todo"`
- `propagate_wip_to_ancestors` is guarded by this boolean flag

# Proposed Change
1. Add `enum YakState { Todo, Wip, Done }` in `src/domain/`
2. Implement `Display` and `FromStr` for serialisation (keep "todo"/"wip"/"done" strings at boundaries)
3. Replace `state: String` with `state: YakState` in the `Yak` struct
4. Replace string comparisons with pattern matching
5. Remove `validate_state()` — the type system handles it
6. Keep `FieldUpdatedEvent` using strings (event store boundary) — convert at the edge

# Scope
- `src/domain/yak_map.rs` — core changes
- `src/domain/mod.rs` — validate_state removal, enum definition
- `src/application/*.rs` — callers of update_state
- `src/adapters/yak_store/*.rs` — serialisation boundary
- `src/adapters/event_store/*.rs` — event replay
- Tests throughout

# Definition of Done
- `YakState` enum used everywhere internally
- String conversion only at serialisation boundaries
- All tests pass: `dev check`
- The original mutant (`&&`→`||`) is killed or made impossible
