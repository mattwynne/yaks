# Add "blocked" state

Add a fourth state to yaks: todo, wip, blocked, done.

"blocked" means "needs external input to proceed." Covers
agent stuck, waiting for review, blocked by dependency.

See GitHub issue #5 (mrdavidlaing feature request for
"waiting" state — same concept, naming is "blocked").

## Display

Icon: ⏸ (pause, U+23F8)
Color: yellow/amber (\x1b[33m)

Tree example:
  ○ alpha
  ├─ ● beta
  ├─ ⏸ gamma
  ╰─ ✓ delta

## State transitions

All transitions between all states are valid, same as
today. No restrictions on which state you can move to.

## Filtering

"blocked" is not-done. is_done() stays as state == Done.
No new --only filter value needed for v1.

## CLI changes

- `yx state <name> blocked` — sets state to blocked
- `yx start <name>` — transitions from blocked to wip
  (currently only handles todo → wip)
- `yx done <parent>` — fails if any child is blocked
  (same as wip/todo), unless --recursive

## Propagation

No automatic propagation for v1. That's a separate yak
(status propagation). Blocked is just another manually-
set state.

## Schema

No migration needed. States are stored as plain text
blobs. Old clients will fail on FromStr with "Invalid
state 'blocked'" which is acceptable.
