# Review finding

Review found that `yx start --recursive` semantics are unclear after adding the start readiness guard.

# Problem

`yx start <yak>` now fails when the yak is not ready. In particular, a parent with incomplete children now fails because descendants implicitly block the parent. The recursive start path lacks coverage, so it is unclear whether it should bypass, reinterpret, or share that readiness rule.

# Decision needed

Decide and specify whether `yx start --recursive` should:

- require the parent itself to be ready before starting anything;
- start only ready descendants and leave blocked/non-ready ancestors or descendants unchanged; or
- be removed, renamed, or changed to a different command/semantics.

# Acceptance guidance

Capture the chosen behaviour with user-visible coverage before changing implementation.
