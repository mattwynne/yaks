# Goal
Document the release process so humans and agents know the intended workflow, while keeping the actual manual steps tiny.

# Likely file
Create `docs/releases.md` and link it from `CONTRIBUTING.md`.

# Content
- Version policy: SemVer, `0.x` expectations.
- Stable channel: `vX.Y.Z` tags.
- Edge channel: `edge` prerelease from `main`.
- Changelog policy.
- One-command release UX.
- What the release script does.
- Recovery notes for failed releases/tags.

# Target release checklist
Ideally the checklist is:

```bash
dev release 0.2.0
git push origin main v0.2.0
```

or, if push is built in:

```bash
dev release 0.2.0 --push
```

Then verify GitHub Actions published the release.
