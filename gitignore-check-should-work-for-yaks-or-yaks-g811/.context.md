# Spec: gitignore check should work for .yaks or .yaks/

## Type
Bug fix

## Goal
The gitignore check should recognise `.yaks/` (with trailing slash) as a valid gitignore entry, not just `.yaks`.

## Problem
`git check-ignore .yaks` returns exit 1 when .gitignore contains `.yaks/` (trailing slash). Both `.yaks` and `.yaks/` are valid gitignore patterns for the directory, but yx only checks for `.yaks`.

This means users who write `.yaks/` in their .gitignore get prompted to add it again on every yx invocation.

## Affected Code

### 1. `src/infrastructure/git_discovery.rs:55`
`is_yaks_gitignored()` passes only `.yaks` to `git check-ignore`. Fix: also check `.yaks/`.

### 2. `src/adapters/local_workspace.rs:38`
Defensive check `line.trim() == ".yaks"` doesn't match `.yaks/`. Fix: match both patterns.
