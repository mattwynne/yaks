# Goal

Add `yx watch <yak>`: a long-running CLI command that watches a yak and its descendants, emitting one NDJSON object per relevant event as changes happen.

# Type

Feature

# Success Criteria

- `yx watch <yak>` resolves the yak by the same fuzzy matching rules as other yak-name commands.
- It emits only events affecting the selected yak or any current descendant.
- Output is NDJSON only: one JSON object per line, no human-readable mode.
- It keeps running until interrupted.
- It flushes each line promptly so another process/agent can consume it.
- It reports clear errors for unknown or ambiguous yak names.
- It is testable without relying on arbitrary sleeps where possible.

# Design Decisions

- Scope is subtree-based: selected yak plus descendants.
- Initial output should not dump historical events; it should watch from “now”.
- NDJSON objects should include enough stable data for agents:
  - event id
  - event type
  - affected yak id
  - affected yak name if resolvable
  - timestamp
  - author
  - raw/narrative event data where useful
- No pretty/human format in v1.
