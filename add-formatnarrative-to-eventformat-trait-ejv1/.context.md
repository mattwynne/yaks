# Goal
Add a format_narrative() method to the EventFormat trait so every event type
must provide a human-readable narrative. Compiler-enforced — adding a new event
type without a narrative is a compile error.

# Files
- Modify: src/domain/event_format.rs — add format_narrative(&self, author: &str) -> String to trait
- Modify: src/domain/events/added.rs — "author added name" / "author added name under parent"
- Modify: src/domain/events/removed.rs — "author removed name"
- Modify: src/domain/events/moved.rs — "author moved name under parent" / "author moved name to root"
- Modify: src/domain/events/field_updated.rs — smart per-field:
  .state=wip → "started", .state=done → "finished", .state=todo → "reset X to todo"
  .context.md → "updated context on X"
  .tags → "tagged X with @foo, @bar" (content has new value)
  name → "renamed X to Y" (if content available) or "renamed X"
  other → "updated field on X"
- Modify: src/domain/event.rs — add format_narrative() on YakEvent delegating to inner types,
  Compacted → "author compacted the event stream (N yaks)"

# Note on field_updated narratives
FieldUpdatedEvent has `content` but it's NOT populated when reading from git
(content lives in the tree, not the commit message). So narratives for
field_updated may not always have the new value. Handle gracefully.

# Definition of Done
- format_narrative() is a required method on EventFormat trait
- All event types implement it with unit tests
- YakEvent delegates and handles Compacted
- All tests pass: dev check
