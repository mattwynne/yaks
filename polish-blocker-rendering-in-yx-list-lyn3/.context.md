# Goal

Make blocked work immediately recognisable and compact in human-facing `yx list` output, addressing GitHub issue #22: https://github.com/mattwynne/yaks/issues/22

# Scope

- Change pretty `yx list` rendering only.
- A todo yak with an active explicit yak blocker or manual blocker uses a red `⏸` indicator instead of the ordinary `○` indicator.
- Keep the yak title in its normal todo styling.
- Replace the verbose grey `not ready:` detail with a concise grey blocker explanation.
- For yak blockers, show the blocking yak title but omit its optional reason from the compact list.
- For manual blockers, show the manual reason because there is no blocking yak title.
- A parent that is unavailable only because it has incomplete children is not presented as blocked.

# Out of scope

- Readiness and blocker domain semantics.
- `yx show`, JSON, Markdown, plain, and IDs output.
- Changing or removing stored blocker reasons.
- Introducing a blocked workflow state.

# Acceptance criteria

- Explicit and manual blockers are visually distinct from ordinary todo work in pretty output.
- With colour enabled, the `⏸` indicator is red and the explanation is dim grey.
- With colour disabled, the same information remains distinguishable through symbols and text.
- Existing non-blocker state indicators and tree layout remain unchanged.
- User-visible change is recorded in CHANGELOG.md.
