# Problem

`yx events watch` currently emits an `EventNotification` envelope whose nested `event` payload is hand-built in `src/application/event_notifications.rs`.

For `FieldUpdated`, the domain event contains the new field value in `content`, but the watch payload only includes:

```json
{
  "type": "FieldUpdated",
  "id": "...",
  "field_name": ".state"
}
```

That means a state change event can say that `.state` changed without saying what it changed to.

This is not just a `FieldUpdated` bug. It is a structural risk: `yx events watch` maintains a lossy parallel schema for event payloads. Any domain event field can be accidentally omitted from the external event stream.

# Decision / ADR Sketch

## Status

Proposed.

## Context

`yx events watch` is a machine-readable event stream used by agents and scripts. Consumers need the actual domain fact, not a partial summary.

The notification envelope is useful because it adds delivery/query conveniences:

- `event_id`
- `event_type`
- `yak_id`
- `yak_name`
- `timestamp`
- `author`
- `narrative`

But the nested `event` value should be the canonical domain event payload, not a manually selected subset.

## Decision

Keep the `EventNotification` envelope, but serialize the nested `event` payload from the domain event's canonical representation.

`yx events watch` JSON should emit full domain event payloads by default.

For example:

```json
{
  "event_type": "FieldUpdated",
  "yak_id": "...",
  "yak_name": "...",
  "narrative": "Matt finished foo",
  "event": {
    "type": "FieldUpdated",
    "id": "...",
    "field_name": ".state",
    "content": "done"
  }
}
```

## Consequences

- `FieldUpdated.content` is visible to event consumers, including state changes (`todo`, `wip`, `done`).
- Future event fields are less likely to disappear from watch output by accident.
- Tests can assert that watch output matches canonical event serialization rather than a hand-written shadow schema.
- Human rendering can still be concise via `narrative`; JSON should remain complete.

## Non-goals

- Do not add old values to `FieldUpdated` as part of this change. The current event records the new value; that is enough for the immediate use case.
- Do not omit or truncate large fields by default. If compact output is needed later, add an explicit flag such as `--compact` / `--no-content`, and make omission explicit in the schema.

# Implementation Notes

Likely direction:

- Derive or implement `Serialize` for domain event payload structs.
- Introduce one canonical JSON representation for `YakEvent` payloads, probably with `type` as a tag.
- Replace the hand-written lossy `event_payload()` mapping in `src/application/event_notifications.rs` with canonical serialization.
- Preserve the existing notification envelope fields.
- Add/adjust tests so a `FieldUpdated` state event includes `content: "done"` (or whichever new value was emitted).

# Acceptance Criteria

- `yx events watch` JSON for `FieldUpdated` includes the new value (`content`).
- The nested `event` payload is generated from the canonical domain event representation, not a manually lossy projection.
- Existing envelope fields remain available.
- Tests protect against losing event fields in watch output.
