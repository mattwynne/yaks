# Goal

Deliver the first end-to-end vertical slice for explicit blockers.

This slice should prove the new blocker model through user-visible behaviour, not just internal plumbing.

# Scope

Implement the smallest useful path through all layers:

- CLI:
  - `yx blocker add <yak> --by <blocker> [--reason <reason>]`
  - `yx blocker rm <yak> --by <blocker>`
  - `yx blocker remove` alias for `rm`
- Events:
  - `BlockerAdded(target, blocker, reason?)`
  - `BlockerUpdated(target, blocker, reason?)`
  - `BlockerRemoved(target, blocker)`
- Projection/read model:
  - current active explicit blockers derived by replaying blocker events
- JSON views:
  - expose explicit blockers as `blocked_by`
  - include blocker `id`, `name`, `state`, and optional `reason`
  - expose `ready` using explicit blockers plus existing hierarchy blockers
- Readiness:
  - `ready = state == todo && no unresolved blockers`
  - blockers include incomplete children and active explicit blockers
- Completion:
  - marking a blocker yak done emits `BlockerRemoved` for each active explicit relationship resolved by that completion

# Vertical Acceptance Scenarios

Add Gherkin coverage first.

## Scenario: A yak blocked by another yak is not ready

```gherkin
Scenario: A yak blocked by another yak is not ready
  Given I have a clean git repository
  And I add the yak "deploy"
  And I add the yak "fix bug"
  When I run yx blocker add deploy --by "fix bug" --reason "crashes in staging"
  And I list the yaks as json
  Then "deploy" should have ready false
  And "deploy" should be blocked by "fix bug" with reason "crashes in staging"
  When I list ready yaks
  Then the output should not include "deploy"
```

## Scenario: Completing a blocker makes the blocked yak ready

```gherkin
Scenario: Completing a blocker makes the blocked yak ready
  Given I have a clean git repository
  And I add the yak "deploy"
  And I add the yak "fix bug"
  And I run yx blocker add deploy --by "fix bug"
  When I mark the yak "fix bug" as done
  Then the log should include a BlockerRemoved event for "deploy" blocked by "fix bug"
  When I list ready yaks
  Then the output should include "deploy"
```


# Out of Scope

Defer broader edge cases unless they are trivial or needed for this slice:

- full cycle/move matrix beyond basic validation needed to keep this slice safe
- migration from legacy stored `blocked` state
- richer human UI/glyph changes
- descendant progress roll-up presentation beyond existing tree output
