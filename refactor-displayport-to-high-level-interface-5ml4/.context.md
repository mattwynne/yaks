# Goal
Replace the low-level DisplayPort methods with high-level ones that
accept value objects. The adapter decides how to render, not the
use case.

# Problem
Current trait has 13 methods like display_breadcrumb, display_section_rule,
display_closing_rule — the use case orchestrates layout by calling them
in sequence. This leaks presentation logic into the application layer
and makes it hard for different adapters to render differently.

# Direction
Replace with something like:
- show_yak(view: YakDetailView) — renders yx show
- show_list(tree: YakTreeView) — renders yx ls
- show_log(entries: Vec<LogEntryView>) — renders yx log
- message(msg: Message) — hints, success, info, warnings

Where YakDetailView, YakTreeView etc. are value objects containing
all the data the adapter needs to render a complete view.

# Why This Matters for Ratatui
The low-level interface forces ratatui to render piecemeal — one
Viewport::Inline per method call. A high-level interface lets
TuiDisplay compose a full ratatui frame with proper layout
(e.g. header box + context + fields in a single render pass).

# Sequencing
This should happen BEFORE converting more methods to ratatui,
otherwise we'd convert them to the old interface then immediately
refactor. Do this refactor first, then yx show and sync spinner
build on the new interface.

# Definition of Done
- DisplayPort has high-level methods accepting value objects
- Use cases construct and pass value objects
- ConsoleDisplay and TuiDisplay both implement new interface
- All existing Cucumber tests pass unchanged
- ConsoleDisplay output unchanged (no visible regression)
