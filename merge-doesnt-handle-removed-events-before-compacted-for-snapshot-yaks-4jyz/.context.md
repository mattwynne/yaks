# Bug

The orphan detection in `merge_event_streams` (mod.rs lines 92-97)
only moves pre-Compacted events to post-Compacted if their yak ID
is NOT in the snapshot. It ignores events for yak IDs that ARE in
the snapshot — including Removed events.

When a stale repo syncs with a compacted remote, Removed events
from the remote's post-compaction period can sort before the
local Compacted event (by timestamp). The orphan check skips them
because the yak ID exists in the snapshot. On replay, those
removals are buried pre-compaction and never applied, so removed
yaks reappear as zombies.

# Fix

The orphan detection should also move pre-Compacted events that
conflict with the snapshot state — specifically, Removed events
for yaks that exist in the snapshot must be placed after it.
