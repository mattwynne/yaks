# Goal

Make `yx events wait-for-next --help` show the complete list of supported domain event type names.

# Type

Feature

# Rationale

`wait-for-next` accepts PascalCase domain event type names. Users should not have to read source code to know the valid values.

# Success Criteria

- `yx events wait-for-next --help` includes all currently supported event type names.
- The list is generated from the same source of truth used by event-type validation, so adding/removing event variants updates help and validation together.
- Help remains concise and readable.
- Existing `wait-for-next` validation behaviour is unchanged: PascalCase names only.

# Notes

Current event names include examples such as `Added`, `FieldUpdated`, `BlockerRemoved`, `ManualBlockerAdded`, `Compacted`, and `Migrated`.
