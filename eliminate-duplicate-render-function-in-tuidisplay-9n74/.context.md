## Problem

`src/adapters/tui_display/mod.rs` has two nearly-identical render functions:

1. `render_header_box` (~line 113) — takes primitives (`&[Name]`, `&Name`, `&str`, etc.)
2. `render_show_header_box` (~line 271) — takes `&YakDetailView`

All unit tests exercise `render_header_box` via the `draw_test_header_box` helper.
The production code path (`show_yak`) calls `render_show_header_box`. So the
entire production render function is untested, and a mutant survived:

```
src/adapters/tui_display/mod.rs:297:12: delete ! in render_show_header_box
```

## Plan

1. Delete `render_header_box`, `draw_header_box` helper, and `header_box_height`
2. Create a new test helper `make_detail_view(...)` that builds a `YakDetailView`
3. Create a new test helper `draw_test_show_header_box(width, &YakDetailView)` that:
   - Calculates height from the view (same logic as `show_yak` method ~line 415)
   - Creates a `TestBackend` terminal
   - Calls `render_show_header_box`
   - Returns the terminal
4. Update ALL existing tests to use the new helpers
5. Verify: `cargo test` passes
6. Verify: `cargo mutants --file src/adapters/tui_display/mod.rs -e 'render_header_box' --timeout=60` — the mutant at line 297 must be killed

## Key details

- `YakDetailView` is in `src/adapters/views.rs` with fields: `id`, `breadcrumb: Vec<YakChildView>`, `name`, `state`, `created_at` (String), `created_by` (String), `children: Vec<YakChildView>`, `short_fields`, `long_fields`, `tags`, `context`, `has_context`
- `YakChildView` has: `id`, `name`, `state`
- The old `render_header_box` takes `Timestamp` and `Author` and formats them; the new one takes pre-formatted strings from the view. The test helper should pass pre-formatted strings.
- Height calculation (from `show_yak` method):
  ```rust
  let has_breadcrumb = !view.breadcrumb.is_empty();
  let mut height: u16 = 3;
  if has_breadcrumb { height += 1; }
  height += view.children.len() as u16;
  if !view.short_fields.is_empty() { height += 1 + view.short_fields.len() as u16; }
  ```
