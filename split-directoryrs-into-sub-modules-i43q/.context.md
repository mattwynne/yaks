## Problem

`src/adapters/yak_store/directory.rs` is 1,435 lines and growing, with no decomposition into sub-modules. It handles file I/O, yak CRUD, child rescue on delete, slug management, and field serialization all in one file.

By contrast, the event store's `git.rs` has already been partially split out into `commit.rs`, `tree.rs`, `sync.rs` — showing the pattern works.

### Suggested splits

- File/directory operations (create, delete, rename, rescue_children)
- Field serialization/deserialization (.state, .name, .id, .context.md, custom fields)
- Listing/querying (list_yaks, get_yak, fuzzy_find)
- Tests (already in a `mod tests` block but could be a separate file)

### Impact

Low-medium — readability and navigability. No behavioral change.
