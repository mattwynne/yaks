# Goal
Make the existing Claude Code discovery path for shared repository skills explicit and regression-tested.

# Files
- Verify: `.claude/skills` remains a tracked symlink to `../skills`
- Add focused coverage under `tests/shellspec/` for the discovery link and canonical SKILL.md targets
- Modify: `CONTRIBUTING.md` with the canonical skill location and Claude Code loading behavior

# Test Approach
Write one failing ShellSpec example that asserts the project skill location resolves to the canonical `skills/` directory and every immediate skill directory contains `SKILL.md`; then make the minimum documentation or layout change needed for green.

# Definition of Done
- Automated coverage fails if `.claude/skills` is missing, copied, or points somewhere other than `../skills`.
- Coverage verifies each shared skill has a readable `SKILL.md` through the Claude project path.
- CONTRIBUTING.md explains that `skills/` is canonical and `.claude/skills` is the Claude Code discovery bridge.
- No duplicate skill bodies are introduced.
- Focused ShellSpec tests pass.
