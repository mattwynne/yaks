# Goal
Make the retained map, prepare, and work workflows available automatically when a Claude Code contributor opens this repository.

# Design
Claude Code does not auto-install repository plugins: project-scoped plugins still require each collaborator to install them locally. Use automatically discovered project skills under the existing `.claude/skills -> ../skills` bridge. Keep `plugins/yx/skills/{map,prepare,work}` as the distributable namespaced `/yx:*` plugin workflow and add only thin project entry points or another single-source arrangement; do not duplicate the full skill bodies.

# Files
- Preserve: `.claude/skills -> ../skills`
- Add or modify: automatic project-skill entry points under `skills/`
- Reuse: `plugins/yx/skills/map/SKILL.md`
- Reuse: `plugins/yx/skills/prepare/SKILL.md`
- Reuse: `plugins/yx/skills/work/SKILL.md`
- Modify: `CONTRIBUTING.md`
- Add focused coverage under `tests/shellspec/`

# Test Approach
Write one failing ShellSpec example proving a fresh checkout exposes all three contributor workflows through Claude's project-skill location without a plugin install, then implement the smallest single-source bridge.

# Definition of Done
- A contributor starting Claude Code in the repository can discover and invoke map, prepare, and work without installing the yx plugin.
- The installable plugin still provides `/yx:map`, `/yx:prepare`, and `/yx:work` outside this repository.
- Project and plugin entry points share one authoritative workflow body or have an automated no-drift guarantee.
- CONTRIBUTING.md explains automatic project loading and optional plugin installation for other repositories.
- Focused tests pass.
