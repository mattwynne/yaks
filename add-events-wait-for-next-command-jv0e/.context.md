# Goal
Add `yx events wait-for-next <yak> <event-type> [--timeout <duration>]` for agents/tools that need a bounded one-shot wait for a specific domain event.

# Files
- Modify: `src/main.rs` to add `EventsAction::WaitForNext` and route it.
- Modify: `src/application/event_watcher.rs` or create a small use case wrapper for wait-for-next mode.
- Create/modify: `features/events.feature` for acceptance coverage.
- Modify: `tests/features/steps.rs` and `tests/features/full_stack_world.rs` if command-spawning steps are needed.

# Test Approach
- Add Gherkin scenarios for:
  - `yx events wait-for-next project BlockerRemoved` emits the next matching event in the watched subtree and exits `0`
  - non-matching event types are ignored while waiting
  - timeout exits non-zero, stdout is empty, and stderr mentions the event type being waited for
  - unsupported event type fails clearly without waiting
- Unit-test event-type parsing/matching if not covered in the shared watcher slice.

# Definition of Done
- `wait-for-next` emits exactly one matching compact NDJSON event then exits `0`.
- Timeout behaviour follows the agreed contract: non-zero, stderr-only timeout message, stdout remains pure domain-event NDJSON.
- Waiting for computed/projected state remains out of scope.
- Acceptance and unit tests pass; run `dev check` before commit.
