# Goal

Fix compaction so it snapshots and replays the whole `YakMap` aggregate state, not just `Vec<Yak>`.

# Decision

Use the architectural cleanup option: introduce an explicit aggregate snapshot type rather than patching `Compacted(Vec<Yak>, Vec<YakId>, ...)` ad hoc.

Compaction should snapshot enough `YakMap` state to replay to the exact same domain state.

# Problem

`YakMap` is the aggregate root. `Yak` is only one entity/state record inside the aggregate.

Current compacted events snapshot only:

```rust
Compacted(Vec<Yak>, Vec<YakId>, EventMetadata)
```

But explicit blocker relationships live on `YakMap`, not on individual `Yak`s. `apply_compacted` clears `self.blockers` and restores only yaks plus manual blocker compatibility fields, so active explicit blockers can be lost by compaction.

# Target Design

Introduce a domain snapshot type, e.g.

```rust
pub struct YakMapSnapshot {
    pub yaks: Vec<Yak>,
    pub removed_yak_ids: Vec<YakId>,
    pub blockers: Vec<BlockerSnapshot>,
    pub manual_blockers: Vec<ManualBlockerSnapshot>, // or equivalent explicit representation
}

pub struct BlockerSnapshot {
    pub target: YakId,
    pub blocker: YakId,
    pub reason: Option<String>,
}

pub struct ManualBlockerSnapshot {
    pub target: YakId,
    pub reason: String,
}
```

Then change compacted/migrated events to carry the snapshot:

```rust
Compacted(YakMapSnapshot, EventMetadata)
Migrated(YakMapSnapshot, EventMetadata)
```

Exact shape can vary, but the snapshot should represent aggregate state explicitly rather than relying on `Yak` fields as an accidental carrier.

# Acceptance Coverage

Add a failing feature scenario before implementation:

- Given two yaks, `deploy` and `security review`
- And `deploy` is blocked by `security review` with a reason
- When I run `yx compact --yes`
- Then listing/showing JSON still reports `deploy` as `ready: false`
- And `deploy.blocked_by` still contains `security review` with the reason

Also cover manual blockers if not already covered by migration/compaction scenarios.

# Implementation Notes

Likely affected areas:

- `src/domain/event.rs` event shape / parsing / formatting
- `src/domain/yak_map.rs` snapshot creation and `apply_compacted`
- event store adapters:
  - `src/adapters/event_store/git.rs`
  - `src/adapters/event_store/tree.rs`
  - `src/adapters/event_store/memory.rs`
- projections/read-model rebuild paths
- compact feature tests and unit tests

Consider backwards compatibility for old compacted events if any can exist in repositories already. If old compacted events are still parseable as `Vec<Yak>`, migrate them to `YakMapSnapshot` with empty blocker collections.

# Definition of Done

- Compaction preserves active explicit blockers and manual blockers.
- Replaying a compacted event reconstructs the same `YakMap` aggregate state as before compaction.
- The compacted event model makes it hard to forget aggregate-level state in future.
- Feature and unit tests cover blocker preservation through compaction.
- Existing migration compatibility tests still pass.
