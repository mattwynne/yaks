# Goal

Make parent yak readiness reflect child completion.

# Current Behaviour / Findings

The current domain model mutates ancestor workflow state when child state changes:

- `YakMap::update_state` detects `todo -> non-todo` transitions and calls `propagate_wip_to_ancestors`.
- `propagate_wip_to_ancestors` changes todo ancestors to `wip` and emits `.state = wip` events.
- When a child later becomes `done`, ancestors are not moved back to `todo`; the parent remains `wip`.
- If a done child is reopened, `demote_done_ancestors_to_wip` changes done ancestors to `wip`.
- `validate_children_complete` already prevents marking a parent done while direct children are incomplete.

Relevant files:

- `src/domain/yak_map.rs`
- `src/domain/yak_state.rs`
- `src/application/set_state.rs`
- `src/application/start_yak.rs`
- `src/application/list_yaks.rs`
- `src/adapters/views.rs`
- `src/adapters/user_display/mod.rs`

# Desired Behaviour

- A parent's workflow state should not be implicitly changed to `wip` just because work starts on a child.
- A parent with incomplete children should be considered unavailable / not ready.
- When the final incomplete child becomes `done`, a todo parent should become ready/actionable again by derived readiness, not by a surprising state mutation.
- Prefer deriving readiness from the child tree rather than keeping parent state in sync with child state events.

# Recommended First Slice

Keep this yak focused on the parent/child rule, before generalising to explicit `blocked_by` relationships.

Implement domain semantics along these lines:

- Remove implicit ancestor promotion to `wip` when a child leaves `todo`.
- Replace done-ancestor demotion-to-`wip` with demotion-to-`todo`, because reopening a child makes the parent incomplete/unavailable rather than actively in progress.
- Add/centralise a domain query for parent readiness, e.g. a yak is ready when:
  - its workflow state is `todo`; and
  - all direct children are `done`.
- Treat direct children as sufficient because a child should not be `done` unless its own children are done; descendants are therefore covered by the existing invariant.

# Out of Scope For This Yak

- Replacing the stored `blocked` state entirely.
- Adding explicit sibling `blocked_by` relationships.
- Migrating existing historical yaks that were already auto-promoted to `wip` by old events.
- Final UI design for showing workflow state vs availability; that belongs in `update list ready and wip semantics` unless a tiny display change is needed to prove this rule.

# Acceptance Criteria

- Starting / setting a child yak to `wip` does not emit `.state = wip` events for ancestors.
- Starting / setting a child yak to `wip` leaves todo ancestors' stored workflow state as `todo`.
- A todo parent with any non-done direct child is not considered ready.
- A todo parent whose direct children are all `done` is considered ready.
- Reopening a child of a done parent demotes the parent to `todo`, not `wip`.
- Existing prevention of marking a parent done with incomplete children continues to pass.
- Domain tests cover the above transitions.

# Design Note

This intentionally separates workflow state from availability without yet introducing a full availability model. The follow-up yak should decide how this derived readiness is exposed in list/show/JSON output.
